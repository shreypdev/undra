Error codes

Every diagnostic Undra raises, from a macro at compile time, from schema validation, from the runtime or from the undra command, has a stable code, a fixed shape and a fix. The link at the end of each message lands on its code below.

How to read one

A diagnostic says what is wrong, why the rule exists and how to fix it. This one is verbatim from the macro test suite:

text
error[undra::E0004]: callback `Arc<dyn Listener>` cannot be a field of a record or enum (`Listener` is a callback interface)
  = note: a callback is an instance with a lifetime, not a value: it cannot be copied, compared, stored in a record or mirrored from a signal
  = help: keep an id or a record here, and take the callback as a parameter of the method that needs it
  = docs: https://shreypdev.github.io/undra/docs/errors.html#E0004

E0001 unsupported type in a public position#

Raised by macros, schema validation, the Encode/Decode bounds.

unsupported type in a public position (lists the type and the allowed set); includes i128/u128 (the help points at Decimal, Uuid or a String newtype), DateTime<Local> and DateTime<FixedOffset> ("convert to Utc; offsets do not cross"), a type of the uuid, chrono, time, rust_decimal or bytes crate that only that crate has (DateTime<Utc>, OffsetDateTime, TimeDelta, ..) spelled without the matching feature of undra (one error naming the feature), a Lazy<T> that is not a store field, or is inside a Signal, Computed or DerivedList (ADR-043), a DerivedList field without its row type (ADR-039), Handle (no schema type; an object crosses as Arc<T> or &T, ADR-040), Arc<T> of a built-in or an Rc, a Result whose error type is not a #[undra::error] enum, a Ctx parameter that is misplaced (on a method, not first, or &mut), and a type used as a value that cannot cross (an Encode/Decode bound that is not met: a struct without #[undra::api])

What you seeWhyFix
Plain cannot cross the boundary by valuea value crosses as a scalar, String, Bytes, Vec, Option, a map, Duration, Timestamp, Uuid, Decimal, or a type declared with #[undra::api] (records, enums) or #[undra::error]; an object (#[undra::api] impl) crosses by handle, never as a valuedeclare Plain with #[undra::api], or return a record with the data the platform needs; a type of the uuid, chrono, time, rust_decimal or bytes crate crosses once you enable that feature of undra
() cannot be used as a field() occupies zero bytes on the wire, so it is only legal as a return type or as a variant without fields; Vec<()>, Option<()> and maps of () defeat length validationremove the value, or use bool if you need a marker
DateTime<Local> cannot cross the boundarya Timestamp is an instant in milliseconds since the Unix epoch, in UTC; a date-time with a local time zone or a fixed offset has no one value every platform reads alike, and the offset itself would be lostconvert to Utc (value.with_timezone(&Utc)) and spell DateTime<Utc>; offsets do not cross
DateTime<FixedOffset> cannot cross the boundarya Timestamp is an instant in milliseconds since the Unix epoch, in UTC; a date-time with a local time zone or a fixed offset has no one value every platform reads alike, and the offset itself would be lostconvert to Utc (value.with_timezone(&Utc)) and spell DateTime<Utc>; offsets do not cross
DerivedList needs the type of its rowsa derived list is a Vec of rows the platforms mirror, so the schema needs the row type, written as the one type argumentwrite DerivedList<Row> for visible, with the type the pipeline's build() produces
&str cannot cross the boundaryreferences have no wire representation; every value crosses by copyuse an owned String

Runtime messages#

The JavaScript runtime (@undra/runtime) throws and logs these. Its production build (what vite build, webpack in production mode and anything else that asks for neither the development nor the react-native condition resolve) says a code, the values and a link instead of a sentence, so a page does not carry the prose of an error whose class, kind and fields it already has: T0017: callSync, remote; see https://shreypdev.github.io/undra/docs/errors.html#T0017. Its development build (Vite's dev server, Vitest, React Native) says the sentence. Both throw the same classes with the same kind and fields; only message differs, so nothing a program can branch on changes. Text the runtime hands on as data, the field of a port's typed error (which the core receives) and a WebSocket close frame's reason (which the peer receives), is not a message: it is the same sentence in both builds. Codes are never reused.
