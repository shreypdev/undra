# SDE - React Native 0.86 verification (wt/rn-086, 2026-10-05)

Question: does `@undra/react-native` work on React Native 0.86, the newest minor below the 0.87 the playground
is built on? Answer: **yes, 0.86.3 is verified** on both phones by the on-device checks. No change to
`runtimes/rn`, the wire, the C ABI or any generated shape. The only edit is `docs/REACT_NATIVE.md`.

## Method

A scratch copy of the repository sources outside the tracked tree
(`/private/tmp/claude-501/.../scratchpad/rn086`, never committed), so the playground's relative links
(`../../../runtimes/...`, `../build/ios`, `../generated/ts`) and its `metro.config.js` stayed as they are.
In the copy's `examples/playground/rn`:

* `react-native` 0.87.1 -> **0.86.3** (`npm view react-native@0.86 version`: 0.86.0, .2, .3 exist; .3 is the
  newest), `@react-native/babel-preset`, `eslint-config`, `metro-config`, `typescript-config` 0.87.1 -> 0.86.x
  (0.86.3 each), `package-lock.json` and `ios/Podfile.lock` removed, `npm install` (738 packages, 10 s).
  `hermes-compiler` resolved to 250829098.0.17; `@react-native-community/cli` stays 20.2.0.
* New Architecture, bridgeless and Hermes as the playground has them (`newArchEnabled=true`,
  `hermesEnabled=true`, the Podfile unchanged).
* The core: `target/debug/undra build -C examples/playground --platform rn --release` in this worktree (build
  outputs are git-ignored), copied into the scratch copy.
* A distinct application id and bundle id (`dev.undra.rn086`) in the copy only, so the shared simulator and
  emulator, which already carry `dev.undra.playground.rn`, were not overwritten; the copy's
  `scripts/rn-device-checks.sh` has the id, the activity (`dev.undra.playground.rn.MainActivity`) and, for the
  shared emulator, no RN24 (Home key) and RN25 (airplane mode) phases. Both test apps were uninstalled after.

## The one thing 0.86 needed that the playground does not have

Not an API of the module: the app's Android toolchain. The playground's Android project is the 0.87 template's
(Gradle 9.4.1, Kotlin 2.2.0, compileSdk 37, build-tools 37.0.0). On 0.86.3 the first `assembleRelease` failed in
`:gradle-plugin:settings-plugin:compileKotlin` ("Incompatible classes were found in dependencies",
`kotlin-stdlib-2.3.0.jar`): Gradle 9.4.1 ships Kotlin 2.3.0, which cannot read the classes 0.86's Gradle plugin
is compiled against. 0.86's template (`@react-native-community/template@0.86.3`) uses Gradle 9.3.1, Kotlin
2.1.20, compileSdk 36, build-tools 36.0.0; with those the build passes (NDK 27.2 kept; the template asks for
27.1, not installed here). Recorded in the "Requirements" paragraph of `docs/REACT_NATIVE.md`.

## Not covered

* 0.82 to 0.85 (the peer range `>=0.82` is unchanged: no run says it is wrong, none says it is right).
* Debug builds on Metro, JavaScript reload, and RN24 and RN25 on Android.
* `npm run test:contract` and `cpp/test/run.sh` as a whole: neither loads React Native, except `run.sh`'s step 3,
  which was run by hand above.
* Observation, not a 0.86 matter: on Android the RN18 line reports a 2 MiB row as a CursorWindow size error
  ("Row too big to fit into CursorWindow") and the check passes; iOS reports the row round-tripping. Same check,
  platform SQLite limits; not compared with a 0.87 run.

Time: about 25 minutes wall, most of it builds on a shared Mac.
