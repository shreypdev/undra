## Verdict

Merge. One finding would have turned the Site job red (the recipe's description over `check-links.mjs`'s limit); it is closed. The claim
of the ADR holds on every axis measured below, the builder survives the awkward names, every committed tree is a fresh generation, and
the two wording findings are closed. Nothing is open.

## Confirmed by measurement (the claim, scratch package `swift-tools-version: 6.2`, platforms macOS 14)

Targets on the `ports` golden and the runtime; each built on its own (`swift build --target`), exit codes as stated, no warnings in any:

* `ModePlain` (`.defaultIsolation(MainActor.self)`): a stateless `final class MyClock: Clock` (sync), a `final class MyKv: Kv` whose
  state is a `let` and whose async witnesses read a `@MainActor` class's property with `await Session.shared.cache[key]` and with
  `await MainActor.run { .. }`, a `final class MyHttp: Http` with `throws(GoldenPorts.HttpError)`, and the three registrations: compiles.
* `ModeClosures` (the mode): `clockPortImpl(nowMs:monotonicNs:log:)`, `httpPortImpl(request: { req async throws(GoldenPorts.HttpError) in .. })`
  reading `await Session.shared.online`, `kvPortImpl(get:set:list:flush:)` reading main-actor state both ways, `flush: { () throws(GoldenPorts.FsError) in }`,
  into `Adapters([PortImplAdapter(..)])`: compiles.
* `ModeState` (the mode): a conformer with `var store: [String: [UInt8]]` and no lock: refused,
  `error: stored property 'store' of 'Sendable'-conforming class 'BadKv' is mutable` (so the conformer is inferred nonisolated, as the ADR says).
* `ModeSyncBad` (the mode): `nowMs: { Session.shared.offset }`: refused,
  `error: main actor-isolated static property 'shared' can not be referenced from a Sendable closure` and
  `error: main actor-isolated property 'offset' can not be referenced from a Sendable closure`.
* `ModeWitnessBad` (the mode): a synchronous witness `func nowMs() -> Int64 { Session.shared.offset }`: refused,
  `error: main actor-isolated property 'offset' can not be referenced from a nonisolated context`.
* `ModeNoClause` (the mode): `httpPortImpl(request: { req in throw .. })` without the clause: refused,
  `error: invalid conversion of thrown error type 'any Error' to 'HttpError'` at the closure; the builder's doc names the fix.
* `PlainApp` (no setting, the 1.1 app): the `ModePlain` file as is, un-annotated methods: compiles. `Swift5App` (`.swiftLanguageMode(.v5)`):
  the same file: compiles.
* `InMode` (the mode): the whole generated tree of the golden (all eight files) compiled inside a module under the setting: compiles.
  `InModeOld`: the same with the pre-piece `Ports.swift` (`git show 453fb6c:..`): fails with exactly the ADR's four errors
  (`call to main actor-isolated instance method 'nowMs()' in a synchronous nonisolated context`, `monotonicNs()`, `log(level:target:message:)`,
  `main actor-isolated instance method 'flush()' cannot be called from outside of the actor`). The modifier is load-bearing.
* `GoldenSwift5` (`.swiftLanguageMode(.v5)`): the generated tree itself in Swift 5 mode: compiles. The generated package's floor is
  `swift-tools-version: 6.0` with `swiftLanguageModes: [.v6]`; a Swift 6.0 compiler was not available here either (see Not verified).
* `Awkward` / `AwkwardApp` (the mode): a sync port with methods `args(args:)`, `r(r:)`, `result()`, `error(error:) throws(AwkwardError)`,
  `impl()`, generated by the new test below and compiled in both forms (a conformer and the builder with five closures): compiles.
  (`self` cannot be a Rust method or parameter name, so it has no Swift case; a port with no methods is refused by the macro,
  `port trait .. has no methods`, `crates/undra-macros/src/impl_/port.rs`.)

## Confirmed by reading

* The builder's table entries are the protocol adapter's code with one difference, the call (`<method>(a, b)` for `impl.<method>(label: a, ..)`):
  `port_table` and `port_method` are shared, `PortTarget` selects the callee, and the decode, `finish`, encode and the `catch let .. as E`
  lines are identical in every regenerated `Ports.swift` (the `ports` golden's three ports, the playground's, the cookbook's `Haptics`).
* Overloads: `<name>PortImpl(_:)` and `<name>PortImpl(<labels>)` never collide (labelled parameters against one unlabelled), including a
  one-method port.
* `naming::avoid` appends `_` until free, so a method named like a local renames the local and pushes a parameter of the same name one step
  further (`args_` / `args__`); no entry declares a name that shadows its closure.
* The two fixtures have no absolute path and no timing; the main-actor pass gates on `swift --version` `>= (6, 2)` and prints its skip, and
  `UNDRA_REQUIRE_TOOLCHAINS=1` does not turn that skip into a failure (an older CI image stays green with the fixtures compiled in the default build).
* The record's migration note is in the voice of `crates/undra-cli/src/migrations.rs` (backticked identifiers, the ADR at the end, one New
  for the builder and one Changed for the modifier) and says what was measured.
* `docs/SPEC.md` section 10 has both shapes and the rule as measured. The generated doc comments say the rule in five lines on the protocol
  and four on the builder (R3: no wrapper, no reflection, a Swift reviewer reads only this file).
